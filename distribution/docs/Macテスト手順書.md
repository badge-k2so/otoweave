# OtoWeave Mac (Apple Silicon / Intel) テスト手順書

対象機種の目安: MacBook（M1/M2/M3など Apple Silicon搭載）、メモリ8GB以上。
所要時間の目安: セットアップ1〜2時間（うち大半はAIモデルのダウンロード
待ちで、放っておいて大丈夫です）＋テスト45〜60分。

**始める前に用意していただくもの:**

- **Wi-Fi環境** — 約5.3GBをダウンロードします。テザリングやモバイル
  回線では通信量が大きすぎるため、必ずWi-Fiに繋いでください
- **空き容量15GB以上**
- **電源アダプタ** — 長時間かかるため、繋いだまま進めてください

Intel Mac（Core i5/i7など）でも動作します。セットアップが自動で判別し、
Apple SiliconのようなMetal（GPU）高速化なしでCPUのみで動作します。
文字起こし・読み上げは同じ速度で使えますが、AI要約とAIチューターの応答は
Apple Siliconより遅くなります。

> これは **検証中のMac版** です。Windows版に比べて実機での確認がまだ
> 少ないため、うまくいかない操作があっても試用者の責任ではありません。
> 気になった点はすべて「うまくいかないときの連絡方法」の欄に記録して
> ご連絡ください。
>
> **ターミナルにコマンドを打ち込む作業はありません。**
> ファイルを右クリックして「開く」を選ぶだけで、あとは自動で進みます。
> 管理者パスワードの入力も必要ありません。

---

## 1. セットアップ（ファイルを2回クリックするだけ）

> ⚠️ **始める前に Wi-Fi に繋いでください。**
> 約5.3GBをダウンロードします。スマホのテザリングやモバイル回線のままだと、
> 通信量の上限に達したり、高額な通信料がかかったりすることがあります。
> 電源アダプタも繋いだまま、時間に余裕のあるときに始めてください。

1. 受け取ったzipファイルを`ダウンロード`フォルダなどに保存し、
   **ダブルクリックして展開**します。
2. 展開してできたフォルダを、分かりやすい場所（例: `書類`(Documents)
   の直下）に移動します。
3. フォルダの中にある **「はじめに実行.command」を右クリック** して、
   出てきたメニューから **「開く」** を選びます。

   > ダブルクリックではなく**右クリック**なのがポイントです。
   > インターネット経由で受け取ったファイルは、macOSが念のため
   > 最初の1回だけ確認を求めるためです。

4. 「開発元を確認できません。開いてもよろしいですか？」と聞かれたら、
   **「開く」** を選びます。
5. 黒い画面（ターミナル）が開き、日本語で進み具合が表示されます。
   **何も入力せずに、そのまま終わるまでお待ちください。**

これで終わりです。画面に「準備ができました」と出れば成功です。

**セットアップ中に自動で行われること**（合計1〜2時間、大半は待ち時間です）

| | 内容 | 目安 |
|---|---|---|
| 1〜3 | OtoWeave専用のPythonとffmpegを用意する | 1〜2分 |
| 4〜6 | 必要な部品を入れる | 5〜10分 |
| 7 | AIモデル本体（約5.3GB）をダウンロードする | 30分〜1時間半 |

- **管理者パスワードは必要ありません。** もしパスワードを求める画面が
  出たら、それはOtoWeaveとは無関係です（他のアプリの更新など）。
- Homebrew や Xcode といった開発者向けのソフトも**必要ありません**。
  必要なものはすべてOtoWeaveのフォルダの中だけに入り、フォルダごと
  捨てれば元通りになります。
- **途中で止まったり、Wi-Fiが切れたりした場合**は、もう一度
  「はじめに実行.command」をダブルクリックしてください
  （2回目からは右クリックは不要です）。**済んだところはやり直さず、
  続きから再開します。**
- 最後に自動で確認が走り、`[OK]`/`[NG]` の一覧が表示されます。
  `[NG]` の行には日本語で対処方法が書いてあります。
  `[--]` は「任意項目・無くても問題なし」の意味です。
- 表示された内容は `setup_log_mac.txt` と `setup_report_mac.txt` に
  保存されます。フィードバックと一緒に開発者へ送ってください。

### 「開けません」「開発元を確認できません」から進めないとき

macOSの版によっては、右クリック →「開く」でも止まることがあります。
その場合は次の操作で許可できます。

1. 画面左上のアップルマーク → `システム設定` を開く
2. `プライバシーとセキュリティ` を選ぶ
3. 下のほうにスクロールすると
   「"はじめに実行.command"は開発元を確認できないため使用がブロック
   されました」と出ているので、その横の **「このまま開く」** を押す
4. もう一度「はじめに実行.command」をダブルクリックする

### どうしても駄目なときの代わりの方法（上級者向け）

ターミナルを開き、`cd ` と打ってから展開したフォルダをウィンドウに
ドラッグ＆ドロップし、Enterを押してから次を実行しても同じことができます。

```bash
./setup_mac.sh
```

---

### AIモデルについて（手作業は不要です）

文字起こし・要約・チャット・話者分離に使うAIモデル本体は、
「はじめに実行.command」が公開配布元から**自動でダウンロード**して
`models/` と `hf-cache/` に配置します。開発者から別途受け取る必要は
ありません。

- 合計サイズ: 約5.3GB（AI要約用の4Bモデルを含む。メモリ8GBのMacでも
  取得します）
- **必ずWi-Fi環境で実行してください**（モバイル回線では通信量が
  大きすぎます）
- **空き容量は15GB以上**を確保しておいてください
- メモリ4GB級のMacでは4Bモデルを取得せず、AI要約は「じゅんび中」表示に
  なります（AIチャットは2Bで使えます）

うまく取得できなかったモデルがあった場合は、最後に名前が一覧表示
されます。もう一度「はじめに実行.command」を開くと、失敗した分だけ
取り直します。

## 2. マイク権限の許可

初めて録音を試すとき、macOSが「"ターミナル"がマイクへのアクセスを
求めています」（または Python 関連の名前）というダイアログを出します。

1. 表示されたら **「許可」** を選ぶ
2. 誤って「許可しない」を選んだ場合は、
   `システム設定` → `プライバシーとセキュリティ` → `マイク` を開き、
   ターミナル（または該当のPython）のチェックをONにして
   アプリを再起動してください
3. `./verify_setup_mac.sh` の「マイク入力」の行が `[OK]`
   （台数が1以上）になっていれば、権限は正しく通っています

## 3. 起動

普段の起動は、Finderで「OtoWeaveを起動.command」をダブルクリックするだけです
（ターミナルを開き直す必要はありません）。

デモの内容から始めたい場合や、うまく起動しない場合の確認にはターミナルで:

```bash
./run_otoweave.sh
# デモ内容から始めたい場合:
./run_otoweave.sh --demo
```

- ウィンドウが開けば起動成功です。
- **計測**: コマンドを実行してからウィンドウが操作できるまでの秒数を
  メモしてください（体感速度のフィードバックに使います）。

### 起動できない・エラーが出て閉じてしまう場合

まず **「はじめに実行.command」をもう一度ダブルクリック**してみてください。
足りない部品だけを取り直すので、多くの場合はこれで直ります
（済んでいるところはやり直しません）。

それでも直らない場合は、画面に出ている内容と
`setup_log_mac.txt` を開発者に送ってください。

## 4. 確認シナリオ

Windows版のテスト手順（`テスト手順書.md`）と同じ観点を、Mac向けに
まとめたものです。ストップウォッチ（スマホで可）があると便利です。

### シナリオA: 録音

1. 左端の録音アイコンから「マイク」を選び、音量テストで反応を確認
2. 「録音を開始」→ 日本語で2〜3分ほど話す（教科書の音読などでOK）
3. 停止 → ノートが保存されるまでの時間を計測

### シナリオB: 文字起こし

1. 話してから文字が表示されるまでの体感の遅れ（秒）を確認
2. 表示された文字起こしを読み、10文中いくつ間違いがあるかをメモ
3. 「★」「？」「！」のマークボタンを押してみる

### シナリオC: 要約

> **メモリ8GBのMacでの要約は、今回のテストで初めて実機確認する項目です。**
> Apple Siliconはメモリの使い方がWindows機と違うため、8GBでも動く想定で
> 有効にしていますが、実測はまだありません。**遅い・固まる・途中で落ちる
> といったことが起きても試用者の責任ではありません。** 起きたことをその
> まま記録していただけると、それ自体が貴重な結果になります。
>
> 万一「じゅんび中」と表示されて要約ボタンが出ない場合は、シナリオDへ
> 進んでください（2Bでのチャットはどの構成でも使えます）。

1. 「要約を作成」を押す → 完了までの時間を計測
2. 元の話に無い内容が混ざっていないか確認
3. チャット欄で内容について1つ質問し、回答時間と妥当性をメモ
4. **要約の実行中に**`アクティビティモニタ`の「メモリ」タブを開き、
   次を記録してください（8GBで足りるかの判断材料になります）:
   - 「メモリプレッシャー」のグラフの色（緑／黄／赤）
   - 「スワップ使用領域」の値
   - 途中で固まった場合は、何分待ったところで諦めたか

### シナリオD: 読み上げ

1. 文字起こし・要約それぞれで「🔊 読み上げ」を押す
2. `say -v Kyoko` による合成音声が再生されるかを確認
   （聞き取りやすさを5段階でメモ）
3. もう一度押して止まるか確認

### シナリオE: 話者を推定

1. 録音・保存済みのノートを開き、「話者を推定」ボタンを押す
   （録音・文字起こしが両方揃っているノートで表示されます）
2. 完了までの時間を計測
3. 結果が正しく推定されているか（実際に話した人数と一致するか）を確認
4. 必要なら「話者名を変更」で名前を分かりやすく変更する

### シナリオF: 色分け確認

1. シナリオEの後、文字起こし本文で話者ごとに行頭の名前表示の色が
   分かれているかを確認
2. 表示設定（⚙）でダーク/ライトを切り替えても見分けやすいか確認

## 5. うまくいかないときの連絡方法

- 画面が固まった・エラーが出た場合は、**そのままの画面を写真に撮って**
  ください
- 次のログファイルも一緒に共有してください（原因調査に使います）:
  - `~/Documents/LearningAccess/logs/otoweave.log`
    （起動直後のごく初期のエラーだけは一時フォルダに記録されることが
    あります。上のファイルが見つからない場合は、開発者に確認してください）
  - このフォルダの `setup_report_mac.txt`
- 連絡先: ＿＿＿＿＿＿＿＿＿＿＿＿（開発者から共有された連絡手段へ）

## 6. フィードバックの観点

Windows版と同じ `フィードバックシート.md` の欄に加えて、Mac版では
特に次の点を記録してください。

- **処理速度の体感**: 文字起こし・要約・話者推定それぞれで
  「待たされる感じがしたか」（Windows版を使ったことがあれば比較感想も）
- **発熱**: 長時間（要約や話者推定の実行中など）使ったときに
  本体が熱くなったか、ファンの音が大きくなったか
- **メモリ**: `アクティビティモニタ`（Launchpadやスポットライト検索で
  開けます）の「メモリ」タブで、OtoWeave使用中にメモリ不足の警告や
  極端なスワップが出ていないか
- **バッテリー**: 電源に繋がずに使った場合の消費の速さ（気付いた範囲で）

## 参考: Windows版との違い

- 録音・再生: sounddevice（PortAudio）を使用（Windowsは PyAudioWPatch）
- 読み上げ: `say -v Kyoko`（Windowsは Windows標準の Haruka）
- AI要約・チャット: llama-cpp-python を Metal（GPU）有効で利用。
  `verify_setup_mac.sh` の「AI要約・チャット用エンジン」の行で
  有効になっているか確認できます
- Python本体・ffmpeg はOtoWeaveのフォルダ内だけに置かれます
  （Homebrew や Xcode は使いません）
- 日本語文字起こし（ReazonSpeech K2）は PyPI未公開のため、
  セットアップが GitHub から直接インストールします。これが失敗した
  場合は日本語のリアルタイム文字起こしのみ使えない可能性があります
  （セットアップ時の警告と、本書「5. うまくいかないときの
  連絡方法」を参照）
